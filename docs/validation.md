### 加载问题的修复范围

- 观察到 OpenCLI 创建新标签页时可先返回空地址或 about:blank；body 存在不代表目标页面已加载。现先查询本次自建页面的原生导航状态，再短同步探测实际页面与选择器，使用宿主有界截止时间。只检查和关闭自身创建的目标，不采用别人的标签页。
- 页面内长等待会受后台计时器与导航上下文替换影响；公众号正文就绪和稳定采样改由宿主控制。唯一匹配搜索来源后正常点击，读取正文区域、代码块和日期来源；失败包含 open_search / wait_article_body 等明确阶段。
- 前台窗口与显式 goto 的对照不能稳定消除问题；显式 goto 的实验实现后来移除。没有简单延长所有超时，也没有宣称已定位所有平台超时的根因。
- 小红书普通加载失败最多在新建的独立页面恢复一次；成功结果包含 recovery.previous_status 和恢复方式。验证、限流、拒绝访问与结果未知不自动恢复。该做法参考了 [OpenCLI 官方修复讨论](https://github.com/jackwener/OpenCLI/pull/2355) 的新目标恢复思路，代码自行实现，没有复制其新版本代码或升级全局组件。
- 小红书评论区域可能在标题和配文之后才挂载。现额外等待评论区；加载停滞或预算耗尽且未确认结尾时返回 comments_loading_incomplete，保留已读评论，避免“成功零条”的误导。

### 本轮发现并修复的日常问题

- 公众号搜索ref在正常点击后变为原文ref，旧候选没有保存正文缓存，重复读取会再次点击临时来源并可能失败。现在同时关联原搜索记录与已解析原文；旧记录仅按精确search_source_url补关联，不按同标题合并。复验原搜索ref直接使用缓存。显式refresh仍保留原查询和私有访问上下文。
- “图片评论 + 链接”占位曾被计为text，现在标non_text并计入non_text_rows，避免模型把未识别图片当文字反馈。
- 评论参数的replies_limit是每个首层评论的回复上限；客户端曾将它理解成总回复数。README/AGENTS明确该含义，返回字段继续列每层确切数量。
- 首次加载OCR可能超过单张预算。设置流程增加模型预热与独立环境记录；日常超时仍保留已完成图片，可补读。

- 图片逐张原子保存；成功图片与待处理图片分开。取消后可用原内容记录继续。原始页面仍重新确认，图片按笔记与有序资产身份绑定；平台提供稳定图片标识时兼容临时 CDN 地址变化，否则只复用相同地址。检查点与正文缓存半小时，缺图正文不被普通缓存挡住。编译/下载/识别共用图片读取截止预算，访问拒绝和限流停止后续图片请求。
- 真实九图样本：主动在第一张成功后取消，终态 cancelled、已读1张/未读8张。再次读取为 success，`images_reused=1`、`images_processed_this_run=8`、成功9/9。首个单图样本未能产生中途取消，另行保存且不作为恢复成功证据。见 `a4-live-image-resume.json`。
- 评论每批有界读取，返回同文章/资料绑定、半小时有效的 opaque `next_cursor`。小红书保存已返回根评论身份并在重开页面后去重；微博/知乎保存平台游标和溢出缓冲。大编号游标保留字符串，避免精度丢失。深层回复树和全部评论仍不承诺完整。
- 公众号保留段落、代码块、数学比较符号、懒加载图片及日期来源；正常点击与直接原文使用共同正文提取逻辑。真实样本1181字符，正文稳定、结束边界确认、无本地截断。临时签名链接明确标注，不生成虚假的长期原文地址；本机来源按钮保留私有访问上下文。
- 进程中断时，任务恢复保留已经写入的正文和进度，不用一条“已中断”提示覆盖部分结果。

### 调研中发现并修复的客户端/平台问题

1. 当前 Hermes 对 `-t` 的 MCP 发现筛选要求原始服务名 `social-media-read-for-agent`；`mcp-social-media-read-for-agent` 会使已配置服务未启动。修正本机此项工具配置与验证调用，其他工具、模型与账号配置保持原值。首轮未发现工具的失败记录仍在私有状态。

### 真实调研发现并修复的问题

1. 小红书搜索偶发空返回，旧任务仍显示 success。现等待有标题及访问参数的卡片，任一平台未返回资料时保留已完成项并标 partial 或 failed；不是证明平台没有相关内容。仍需跨主题、跨日期观察。
2. OpenCLI 的等待选择器在新页面尚无 body 时使用 MutationObserver(document.body)，已复现 TypeError。改用固定内部选择器和有界就绪轮询，覆盖笔记、评论与公众号；加载超时不再直接解释为删除。
3. 小红书评论在标题出现后尚未加载，曾返回0；增加有界内容等待。图片或表情评论保留未读标识，不静默丢掉；修正回复对象，深层树结构未验证时 depth=null。
4. 同一知乎文章两次早期读取为1762、2357字符；增加正文稳定等待后复测2357字符，仍不声称付费或平台不可见部分可读。
5. 微博与知乎早期评论请求超时；只读网络超时增加最多一次有界恢复，验证、访问拒绝和限流不反复尝试。后续相同微博及知乎文章评论均通过。
6. 错误分类的未限定数字429曾匹配日志中的进程编号，误报限流；现只匹配独立状态码，原误分类记录保留。
7. 图片 CDN 下载曾导致9图样本只读8张或6张。保留每张失败位置及 partial；使用正常来源 Referer、图片指纹及半小时明确缓存。最终 Codex 复测同一9图全部通过，不覆盖前面的失败。
8. 网页以前回看评论历史没有渲染评论；现可回看评论，历史显示文章标题和任务时间，逐图文字独立展开。
9. 长期驻留的 MCP 进程不会随代码自动热更新。当前对话曾继续调用旧代码；停止旧进程后连接不会在该对话自动恢复，出现 Transport closed。正式配置已恢复原名称，最终 Codex 验收使用重新启动的桌面随附客户端并通过。更新后应重连该服务或新开客户端会话，不重复提交平台请求。当前旧对话连接不作为最新版本已连接的证明。
