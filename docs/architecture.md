# 实现结构与后续执行

`网页 / 命令行 / MCP → Engine → 平台适配器 → OpenCLI → 专用 Chrome 资料 → 平台页面`

三个入口共用同一套验证、任务和来源记录。公众号增加了不带 Cookie 的公开 HTTP 补充读取：限制重定向到微信文章、响应大小与时限，验证页不能进入正文。该路径还没有真实成功样本。读取接口只包含固定业务动作。MCP 使用换行 JSON-RPC stdio，支持初始化、工具发现、调用和任务查询；本地 HTTP 服务是网页后端，不是 MCP HTTP 端点。

Python 标准库提供任务池、SQLite 与本地服务，前端不依赖框架。选择这一结构是为了先验证真实读取能力，减少安装成本并保留可替换适配器。以后可在相同的数据契约下增加新的后端，不需要让 Agent 学习每个平台的命令格式。

## 状态与证据

任务状态为 queued、running、success、partial、failed、cancelled、interrupted。搜索结果记录平台、来源、查询词、取得时间和 content_ref；阅读增加正文、正文哈希、取得时间和缓存状态。完整性默认为 unverified，只有原页面对照后才能写入更强结论。原始数据和访问参数保存在私有状态中，对外结果经过脱敏。

模式与浏览器资料分别划分状态目录。专用资料绑定是必选项；当前没有账号身份变更自动检测。不同账号应使用不同资料，禁止把一个资料下的旧缓存解释成新账号读取结果。

## 执行顺序

1. **连接验收**：确认扩展安装在专用资料；选择唯一 context ID；完成桥接与账号只读检查。
2. **平台逐项实测**：使用 examples/research-queries.json 中公开、非敏感测试词，每次最多五条。每个平台读取五篇，逐篇对照标题、作者、日期、正文边界、图片和视频缺失、来源跳转。
3. **修复优先缺口**：公众号搜狗跳转解析；平台字段变化；小红书图文缺口；知乎答案集合来源与摘要降级。禁止静默用摘要充当正文。
4. **用户验收**：用实际产品调研问题演示搜索、选帖阅读、引用、失败恢复。记录结果覆盖边界，不将搜索样本当作市场总体。
5. **稳定性验收**：跨日检查登录过期、撤销扩展、断网、服务重启、缓存刷新、取消和验证码停止。只有通过后才扩展到发布能力。

## 后续发布功能

需要新的业务权限与逐操作确认、草稿预览、账户目标显示、幂等与结果对照。当前读取 MCP 没有发布入口。不能直接把 OpenCLI 所有写命令暴露给模型。

## 已知实现边界

调用上游时限制初始内容 URL 的域名和路径；下游重定向行为仍需要真实测试。无法保证平台接口或扩展更新后继续兼容。程序只停止自身子进程，不会关闭用户的浏览器或平台账号。任务记录保留历史内容，尚未提供自动过期与加密管理。
